# 竞品与领域调研

> 结论先行：eventx 定位为进程内事件总线基座，采用"库定义零依赖钩子、
> 适配器可插拔、项目层组装"的家族模式。不追求与 eventbus / go-bus /
> 消息中间件兼容，只吸收经过验证的发布-订阅语义。

## 调研对象

| 方案 | 定位 | 值得借鉴 | 自用场景下的短板 |
| --- | --- | --- | --- |
| Go 标准库 channel + sync | 原语 | 并发安全、零依赖 | 无主题路由、无订阅管理、无错误语义 |
| asaskevich/EventBus | 进程内 pub-sub | 同步/异步发布、通配符订阅 | 反射重、错误处理弱、与家族生态割裂 |
| gookit/event | 进程内事件 | 过滤、异步、优先级 | API 风格与家族不一致，无 errx/logx 打通 |
| Kafka/RabbitMQ/NATS | 分布式消息 | 持久化、跨进程、重放 | 重、需要部署，进程内场景杀鸡用牛刀 |

## 自研原则

1. **主题路由**：字符串主题 + 层级通配符（`*` / `**`），显式可预测；
2. **错误语义**：同步发布聚合全部订阅者错误（errx.Join），
   异步发布通过错误回调上报；
3. **上下文贯穿**：订阅 handler 接收 context.Context，tracex 可直接注入；
4. **可插拔**：eventx 本身是独立基座；家族库通过零依赖 EventHook +
   eventx/adapters 接入，不强制依赖；
5. **可观测**：可选 logx 日志、Metrics 接口、并发安全、100% 覆盖与 fuzz。
